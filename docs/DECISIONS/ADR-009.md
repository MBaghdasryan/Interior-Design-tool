# ADR-009: Семантический поиск — провайдер за интерфейсом, векторы в таблице, pgvector по мере роста

**Статус:** принято · 2026-10-22

## Контекст
Нужен поиск по названию и описанию на hy/ru/en, «похожие по фото» и подбор аналогов. Кредиты AI-провайдеров на момент решения исчерпаны (Gemini — 402, OpenAI — нет кредитов), Postgres в compose — стоковый `postgres:16-alpine` без расширения `vector`.

## Решение
- Эмбеддинги за интерфейсом `app/search/embeddings.py`: `local` (по умолчанию: многоязычные лексические векторы — хеширование слов и символьных 3–5-грамм плюс расширение по таксономии категорий; без сети и затрат), `gemini` (`gemini-embedding-001`), `off`. Сбой удалённого провайдера → локальный режим с записью ошибки в статус. Векторы разных провайдеров не смешиваются (ключ: provider + model).
- Хранение — таблица `product_embeddings` (JSON), поиск — numpy в памяти (кэш с инвалидацией по числу строк). Миграция 0011 включает `vector`, если он доступен на сервере.
- Визуальный поиск — локальный дескриптор (HSV-гистограмма + ориентации градиентов) по изображениям из собственного хранилища.
- UI честно показывает режим: «многоязычный лексический поиск, не нейросеть».

## Последствия
- Каталог до ~50 тыс. позиций ищется в памяти за миллисекунды. При росте — образ `pgvector/pgvector:pg16` на **новом** кластере (смена alpine→debian на существующем томе меняет collation — только через dump/restore), колонка `vector(768)` и индекс HNSW.
- Качество смыслового поиска без нейросетевого провайдера ограничено лексикой и словарём категорий; включение `SEARCH_EMBEDDINGS=gemini` требует оплаченной квоты и полной переиндексации (`POST /admin/search/reindex`).
